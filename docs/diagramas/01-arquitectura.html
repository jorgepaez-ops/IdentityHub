Arquitectura de Identity Hub y Contabilidad

Servicios del docker-compose.yml actual, con la observabilidad (perfil observability) y el SSO de Contabilidad como cliente OAuth2. Debajo, qué cambia en la producción simulada y su equivalente en la referencia AWS.

Colores: cian = frontend, verde = servicio Go, violeta = datos, naranja = mensajería, ámbar = observabilidad y cliente SSO, gris = utilitario. Línea verde gruesa = ruta principal del usuario; línea roja = flujo OAuth2 con PKCE (detalle en el flujo SSO); línea punteada = scrape o inicialización.

Producción simulada y referencia AWS

La producción simulada es un override de Compose (deploy/docker-compose.prod.yml, make up-prod); la referencia AWS es Terraform validado, no aplicado en ninguna nube (infraestructura/terraform/, despliegue AWS).

AspectoDesarrollo (Compose)Producción simulada (local)Referencia AWS (Terraform)
Entradaweb :8080, api :8081, db, broker, worker y observabilidad publican puertosSolo web publica :8080; el resto queda en la red internaRoute 53 y ACM (TLS), WAFv2 y ALB (443 con TLS 1.3, reglas por Host) hacia web
Imágenesapi, worker y web se construyen localmenteImágenes publicadas, referenciadas por digest (IDENTITY_HUB_*_IMAGE)Las mismas imágenes por digest, desde Docker Hub (ADR 0011)
DatosPostgreSQL y RabbitMQ en contenedores, con volúmenesIgual, con reinicio automático y límites de recursosRDS PostgreSQL 16 cifrado con KMS; RabbitMQ como tarea ECS (decisión D7)
CorreoMailpit captura el SMTPMailpit fuera por defecto (perfil correo-local); exige un relay SMTP real, que el worker aún no autentica ni cifraSES; requiere autenticación SMTP y STARTTLS en el worker (brecha documentada, ADR 0012)
SecretosVariables de .envVariables de .env (el backend no soporta *_FILE)Secrets Manager y KMS
Logs y métricasPerfil observability opcionalMismo perfil, sin puertos al host; rotación de logs 10 MB × 3CloudWatch Logs con retención; sin Prometheus ni Grafana en el Terraform
